# CLAUDE.md — прототип «Яндекс Плюс»

iOS/SwiftUI дизайн-прототип супераппа «Яндекс Плюс»: у Музыки, Кинопоиска и Книг свои табы с главными витринами, плюс кросс-сервисная витрина «Плюс» и общая коллекция «Моё» (Алисы нет с 2026-10-04). Не продовое приложение: моки + бесплатные публичные API. Пользователь (Дима Журавлёв, продуктовый дизайнер в Яндексе) проектирует здесь опыт взаимодействия. Внутренние разделы сервисов глубже главных не проектируем. Сиблинг `~/Repos/MusicPlayer` — предыдущий прототип, источник архитектуры и компонентов.

Здесь только то, чего не вычитать из кода: правила, вкус пользователя, отвергнутое, грабли и открытое. Что готово — в коде и `git log`. Правда — код: запись, разошедшаяся с ним, — дефект, правь запись.

## Четыре правила, нарушение которых обесценит работу

1. **Пиксель в пиксель с Figma.** Числа — замером из макета, не на глаз. Значения, которого в макете нет, не заводить.
2. **120 fps.** Не читать размер вью, от которого зависит её же раскладка, — это уже вешало рендер на 100 % CPU; размеры считать от ширины экрана устройства (`PlusMetrics.screenWidth` — константа процесса, приложение в портрете) и констант. Ничего не писать в `@State` на каждом кадре: покадровое — аналитической функцией времени, в покое `TimelineView` уходит из дерева. Жесты — через transform.
3. **Квота Кинопоиска — 200 запросов в сутки на ключ.** Не жечь отладкой. Остаток — `GET /v1.5/token` (квоту не тратит).

4. **Никаких абсолютных значений под конкретную модель телефона** там, где вёрстка должна подстраиваться (решение пользователя 2026-10-12): ширины экранов, витрин, хедеров, колонок и карточек — от `PlusMetrics.screenWidth`. Карусели — столько же целых карточек, что на 402, правый край следующей карточки торчит ровно как на 402, карточки меняют ширину с сохранением пропорций; сетки — поля и зазоры постоянные, колонки делят остаток. Числа макета на 402 — база для формул, а не готовые ширины.

- Блюр-константы в коде вдвое меньше значения в панели Figma (`GlassSurface.swift`) — менять только все разом.
- SVG из Фигмы с фильтрами (внутренние тени, блюр) iOS рисует плоско — растрировать: `python3 -I scripts/svg-raster.py <svg> <png> <масштаб>` (Quick Look на чёрном и белом, альфа по разнице). Прогрессивный блюр Фигмы SVG передаёт ровным на весь слой — сверять с кадром ноды (`get_screenshot`): капли барабана «Моей волны» так выходили бледными пятнами.

## Сборка и верификация

Только Xcode toolchain (Xcode 26.3). Папка репозитория — `plus-proto-app`, таргет/схема — `PlusProtoApp` (ASCII без дефисов, чтобы модуль не стал `plus_proto_app`), bundle `com.dima.PlusProtoApp`, iOS 26.0, Swift 5, макеты — на ширине 402 pt (iPhone 17 Pro), вёрстка адаптивная: проверка на iPhone 17e, 17 Pro и 17 Pro Max.

```bash
xcodebuild -project PlusProtoApp.xcodeproj -scheme PlusProtoApp -destination 'platform=iOS Simulator,name=iPhone 17 Pro' -configuration Debug build
```

Установка, запуск, отладочные флаги, приёмы проверки — [docs/DEBUG.md](docs/DEBUG.md). У каждого worktree свой хеш в DerivedData: ставить сборку из своего и переустанавливать после каждой сборки — дважды пользователю показали «исправленный» экран со старой сборкой.

**Верификация — руками пользователя, не агентом** (решение 2026-08-25). Агент: собирает проект всегда; один контрольный скриншот (`xcrun simctl io booted screenshot`) — только для новой вёрстки, впервые собранной по макету; в ответе — короткий чек-лист «что посмотреть». Серии скриншотов, пиксельные замеры и прогоны флагов — точечно по фидбеку. Пользователь работает в том же симуляторе, отладочный запуск его сбивает; после запуска с флагами — чистый перезапуск без аргументов. Субагентам симулятор не давать: `simctl … booted` общий. Сомнения снимать замером, а не рассуждением; белый кадр или «глюк simctl» — сперва подозревать баг приложения.

CI ([.github/workflows/build.yml](.github/workflows/build.yml)) — только компиляция на ключах-заглушках.

**TestFlight.** Собирается только из `origin/main` GitHub, не из локальной рабочей ветки: правки сначала в PR и мерж, потом архив из чистого worktree от `origin/main` с копией `APIKeys.swift` (решение пользователя 2026-10-12). Внешней группе «Внешнее тестирование» сборка раздаётся сразу после выгрузки: `python3 -I scripts/testflight-external.py distribute --group "Внешнее тестирование" --since-minutes 20 --whats-new "…"` (`--since-minutes` — ждать именно свежую сборку: в API она появляется не сразу, без этого раздалась бы предыдущая) — ждёт обработки, пишет «Что тестировать», добавляет в группу и отправляет на Beta App Review (ключ App Store Connect API — `~/.appstoreconnect/`, вне репозитория; решение пользователя 2026-10-13). Выгрузка — из Xcode: устройство «Any iOS Device» → Product → Archive → Distribute App → «TestFlight Internal Only» (без ревью; тестеры — участники команды в App Store Connect, до 100) или «App Store Connect» (внешние тестеры и публичная ссылка; первая сборка версии проходит Beta App Review). Таргет — только iPhone (`TARGETED_DEVICE_FAMILY = 1`): вёрстка от 402 pt, на iPad приложение идёт в окне айфона. Подпись под иконкой — «Прото Плюс», запись в App Store Connect — ProtoPlus: чужой бренд на иконке при выпуске с личного аккаунта — первый повод для отказа на ревью внешнего тестирования (2026-10-05). Новое API «с обязательной причиной» (даты файлов, аптайм, место на диске) — в `PlusProtoApp/PrivacyInfo.xcprivacy`, иначе выгрузку отклонят. Сбои тестеров с их комментарием — App Store Connect API тем же ключом: `GET /v1/apps/{id}/betaFeedbackCrashSubmissions`, лог — `/v1/betaFeedbackCrashSubmissions/{id}/crashLog`. Ключи API вшиты в сборку и общие на всех тестеров: квота Кинопоиска кончается быстрее, витрины уходят в моки и дисковый запас.

## Локальные эксперименты Артура

Актуальные правила 2026-10-22: вариант артиста с обтравкой удалён целиком
(флаг, сервис, кеш, крупное имя, отдельная кнопка «Слушать»). Артист круглый.
HomePromoStartPolicy исключает его из первого показа и первого места набора,
включая обновление каталога до взаимодействия. Тоггл полок называется
«Экспериментальные полки на главной».

Pull-to Recently: непрерывное раскрытие до96 с первого движения без ступеней
и пружины. Разрешён только отдельный жест от верха (допуск2); возврат из глубины
в том же жесте не раскрывает. Отпускание сохраняет размер. Следующий свайп
в контент сначала сворачивает Recently за ход до64 pt, остаток того же свайпа
скроллит страницу. HomeRecentlyScrollBridge наблюдает родительский UIScrollView,
не заменяет delegate; ход сворачивания считается по pan translation,
offset корректируется синхронно. Инерция сначала завершает сворачивание.
Закрытие не требует начала точно в нуле и не блокируется небольшим отскоком:
явное движение pan в контент расходуется через consume. Короткий закрывающий
свайп без инерции завершает сворачивание при idle; открытие по-прежнему только от верха.
При уходе состояние сбрасывается. Подписи белые, Play фиксированного размера.

Хаптики: свайп на другую карточку — soft0.7; лайк/дизлайк и достижение полного
раскрытия/закрытия Recently — два light0.7 с интервалом70 мс.
Хаптик карусели определяется геометрией при переходе центра к соседнему слоту,
один раз за жест; генератор soft удерживается и готовится на tracking.
Не зависит от pageID и очередности idle/geometry. Программные переходы и
свайпы, не пересёкшие середину между слотами, не вызывают хаптик.

Бадж альбома «Новое» скрыт, пока intro «Рекомендовать» ожидает первого показа
или развёрнут на этой карточке. Состояние intro общее с парой реакций через
ShowcaseFeedbackState. После сужения капсулы бадж появляется через opacity
за0.2 с; ожидание0.6 с (Reduce Motion0.15) совпадает со сжатием кнопки.
Проверки: sh scripts/check-home-recently-pull.sh и scripts/check-home-promo-start.sh.

Тост дизлайка промо (Figma 464:27924): 256×56, «Будем показывать меньше такого», Text S Medium, текстовый слот114, слева24; справа «Отменить» 94×32, Semibold, зазор12/поле12, без графики. Действие живёт только в текущем тосте; замена, скрытие и таймаут освобождают его. Лайк сохраняет свой прежний тост280 с кнопкой «Сохранить». Проверка: scripts/check-toast-center.sh.

**Движение**
- Плавность — центральное требование: никаких резких подмен, параметры состояния меняются одной анимацией. Морф — на живых вью без `if/else`; содержимое при морфе разложено по конечному размеру и меняет только прозрачность.
- Ничего не меняется на глазах: витрина собирается под заставкой; бар и «Смотреть дальше» обновляются под выехавшим плеером; выдача поиска публикуется целиком и потом не переставляется. Асинхронное не двигает раскладку: место держится заранее, скелетон повторяет геометрию контента, из кэша — сразу.
- Смена списков и текста — последовательно: старое гаснет ~300 мс, новое проявляется ~300 мс, либо через блюр (`.blurReplace`). Одновременный кроссфейд двух полупрозрачных копий — нет; 150 мс — «слишком резко». Скелетон → контент — не смена списков: карточки встают на его место без кроссфейда, проявляются только обложки и подписи.
- Кривые: движение по экрану и смена на месте — ease-in-out; что едет с клавиатурой — её кривой; уходящее уезжает за кромку экрана, а не гаснет раньше. Несрочное — неспешно.
- Скролл-эффекты — чистая функция скролла (smoothstep без излома) и не зависят от анимаций табов, иначе моргает подложка. В покое блюр шапки не нужен — проявляется по скроллу.
- Жесты: экран идёт за пальцем 1:1 с первого пункта; закрыть легче, чем открыть; закреплённое над лентой тянется за оттягом вчетверо медленнее, с мягким потолком (`ServiceTopNavMotion.pullShift`).
- Анимация не врёт и не навязывается: бегущее троеточие читалось как загрузка; видео — только по тапу и одно; вступление витрины — раз за процесс.
- Reduce Motion — всегда своя ветка (обычно только прозрачность); системная настройка важнее требования к переходу.
- Отклик на нажатие — у всего нажимаемого, даже без пресс-стейта в Фигме: круглые кнопки 0.92, с текстом 0.95 (2026-10-17), карточки 0.97, строки списков 0.98 (черты не проседают); ячейки островков дебаг-меню — подсветка; строки островков профиля — без нажатого состояния (правка пользователя 2026-10-13), его кнопки (в т. ч. «+») — с лёгкой хаптикой. Просадка сразу под пальцем, а не после задержки скролла, и у быстрого тапа держится не меньше 0.1 с: `PressScaleButtonStyle` / `.pressScale` (`PressMotion`). Палец на вложенной кнопке («ещё», сердце) достаётся ей.
- Хром не простреливается: тап в зазор между табами достаётся ближайшему табу, в любую точку таббара — не ленте под ним. Зона шире кнопки — `contentShape` под отрицательным отступом, раскладка не едет.
- Хаптика — одна на действие, общим вызовом; у каждой кнопки (лёгкая — сама `PlusButton`, своя — `haptic: .inAction`), кроме «назад» навбара (2026-10-17): табы и фильтры — `TabBarMotion.tapHaptic()`, кнопки плеера — impact light, перемотка — лёгкая трещотка, ✓ — success, ✕ — medium.
- Блюр — один, нижним слоем, прогрессивный и только по контенту: начинается там, где контент заходит под хром. Навигация витрин, профиль, закреплённые чипсы — блюр без затемнения.

## Архитектура

- **Каркас — от MusicPlayer**: свитч `AppTab` + `NavigationStack` на таб, хром (таббар, action bar) в `ZStack` вне стеков, env-объекты из корня, `@Observable`. Вью читает состояние через `@Environment` сама: параметр и ручной `Binding` зависимость не регистрируют.
- **`AppNavigationState`**: таб, пути, слои (`coveredRoute`/`coveredPath`), профиль. Табы переключаются мгновенно. Поп — `removeLast()`: подмена пути убивает обратный зум. Тап по активному табу — к корню, на корне — к началу экрана.
- **Экраны**: фильм — `fullScreenCover` над хромом, дальше — вложенные `CoveredEntityScreen` со своим `BottomChrome`; альбом, плейлист, книга, персоны — пуш с хромом. Переходы — через `navigation.open`, не `NavigationLink`. Зум — `.zoom` с `sourceID` = `EntityRoute`; источник — только миниатюра `showcaseThumbnail()`, и её рисунок обязан умещаться в собственный кадр (система режет портлет по кадру); сдвиг — `padding`, не `offset`.
- **Плееры** — только через `ContentPlayerPresenter` (UIKit-презентация с верхнего контроллера поверх любых слоёв: музыка `.overFullScreen`, кино и читалка `.fullScreen`); открывают их `ActionBarState.watch/read`. Музыка из мини-плеера читалки открывается поверх читалки вторым слоем (`isMusicOverReader`, слот `contentPlayer` занят читалкой), закрылась — снова книга. Круг мини-плеера в читалке выбрасывается свайпом вправо до конца сеанса читалки, музыка играет дальше. Обвязка читалки (верхняя панель «закрыть · обложка · название · две кнопки», нижний блок «Аннотация · таймлайн · четыре кнопки», затемнения сверху и снизу) при открытии скрыта, показывается и скрывается тапом по тексту (`isChromeShown`, макеты `2311:27488`, `2565:25233`, `2565:25462`); мини-плеер при этом стоит на 24 справа и 40 снизу, с обвязкой поднимается на 132, всё — одной анимацией `BookReaderMotion.chrome`. Таймлайн — доля прокрутки аннотации, не страницы книги; кнопки обвязки, кроме закрытия, пока без действий. Свой `fullScreenCover` под плеер не заводить. Под `.fullScreen` экраны уходят с окна и их `.task` перезапускаются — задачи должны быть идемпотентны. Приложение заперто в портрете: альбомный плеер нарисован повёрнутым холстом.
- **Кто включает плеер**: кнопки экранов сущностей («Слушать», «Смотреть», «Читать»); переход по карточке — нет. Сразу играет то, у чего нет своего экрана: «Моя Волна», трек в полной выдаче и в коллекции, карточки «Смотреть дальше» (киноплеер с места остановки). «Продолжить читать» на «Главной» — двумя зонами: тап по тексту — сразу читалка, по шапке (блюр, обложка, прогресс) — экран книги (2026-10-09). Плейлисты отовсюду открывают свой экран — `PlaylistScreen`, по конструкции альбома.
- **Action bar = «продолжить»**: режим задаёт последний запущенный контент, а не таб; снимок на диске. Чип книги (`2001:111014`) — ширина по пропорциям обложки (`ActionBarState.bookCoverAspect`), её же берёт раскладка бара (2026-10-16). Музыку глушат только play/pause и запуск кино. Пилюля музыки сворачивается в круг только при активации поиска (правка пользователя 2026-10-10): смена таба, экраны, закрытие плееров и снятие фокуса её не трогают. Беззвучное видео — `AVAudioSession .ambient`, своя музыка — `.playback` (`AppAudioSession`).
- **«Моя волна»** — поток, а не трек: кнопка экрана, лепестки барабана и карточка «Главной» включают настоящий трек её настроения (`MyVibeTracks`, id `my-vibe-t<трек Deezer>`). Экран Музыки: блок «название + кнопка» посередине между навигацией и барабаном станций (`VibeDrum`, макет `2:6398` файла «ЯПС · Mobile · Current State»): лепестки на дуге окружности R 380 через 18.5°, масштаб 1/0.9/0.8, круг из трёх копий.
- **Звук музыки** — 30-секундные превью Deezer (`MusicAudio`), звучат ровно пока плеер «играет»; трек в плеере — 30 с, прогресс идёт за звуком; по окончании превью — следующий трек очереди (`ActionBarState.queue`, заполняется в точке запуска и пишется в снимок бара; запуск без списка, но с альбомом в id — очередь из треклиста альбома, `fillQueueFromAlbum`; волна — случайный следующий; ни списка, ни альбома — повтор; 2026-10-16). Громкость — в дебаг-меню, по умолчанию 50 %. На холодном старте плеер на паузе — звук сам не включается. Превью ищется по треку в id (`…-t<id>`, `track-<id>`), иначе поиском по исполнителю и названию; ссылка подписана и живёт ~15 мин — запрос мимо кэша.
- **Клавиатура**: корень, корень стека, каждый пуш и слой — `ignoresSafeArea(.keyboard)`; отступ хрома считает `KeyboardObserver`; бар поднимается по `keyboard.isUp` — второе поле ввода тоже раскроет бар.
- **Поиск**: слои — в стеке экрана, где поиск открыт, соседями в `ZStack` (в `.overlay` backdrop-блюр видит пустоту); `SearchNavigationSync` — на корне и на экранах слоя. Возврат из карточки — в выдачу без клавиатуры.
- **Две версии выдачи** — карусели по разделам и сетка вперемешку (`SearchMosaicView`); вид выбирается в дебаг-меню профиля (`SearchResultsStyle`, ключ `searchResultsStyle`; по умолчанию — сетка, 2026-10-12) и меняет и нулевое состояние: у сетки «Искали недавно» тоже сеткой, вся история сразу, без полного списка, в конце — «Удалить историю поиска» (`SearchRecentsMosaicView`). Порядок сетки — `SearchState.mixed`: в первом ряду лучшее из каждого раздела, чьё название отвечает запросу, дальше слияние разделов по весу совпадения со штрафом за повтор раздела подряд; порядок внутри раздела не меняется. Сетка шире каруселей: в ней плейлисты и создатели лучших работ — режиссёры и писатели с фото, сразу за своими фильмами и книгами, с долей их веса. Сетка дописывается порциями только в конец, а когда кончается выдача обзора — один добор полными выдачами трёх разделов.
- **Витрины**: свежий случайный набор на каждый холодный запуск, стабильный внутри процесса (зёрна — `ShowcaseRotation`); позиция промо помнится на сессию. Каталоги живут в корне (`AppRootView`) — экраны табов размонтируются на каждом переключении. Запуск под заставкой, пока витрина не соберётся (данные + обложки, потолок 6 с). «Главная» (мультивитрина, таб `.plus`) — модель `{промо, [блоки]}`, `ForEach` по слоту, а не по контенту; сверху навигация `HomeTopNav` (логотип, Люмен, аватар) — тот же ряд `TopNavRow`, что у сервисных табов, аватар в одной точке; заголовка с врезками нет (2026-10-08). Тогл дебаг-меню «Люмен в поиске» (`LumenDebug`, 2026-10-16) переносит голову из навигации в поле поиска бара вместо лупы (макет `2777:32103`, свои фразы); ролик один на все копии (`LumenHeadPlayback`), между проходами 3 с покоя. Под навигацией — ряд **ПП** («продолженное потребление», `RecentlyRow`, макет `2713:26833`): начатое, свежее первым; «Моя волна» (`2785:32127`, живой шейдер) — в общем порядке, только после главной волны таба Музыки (`openMainVibe`; станции её не пишут); высоты всех плиток — 72, зазор 6 (2026-10-16) (`RecentlyConsumed`, пишется в `ActionBarState.open`, новое — в начало, стартовый набор из 8); фильм и книга по тапу — сразу плеер и читалка, альбом (плейлист) и исполнитель — их экраны; ряд 72, плитки — макетные (80), ужатые целиком (2026-10-13), но скругление 6 (у книги — правые углы) и бордер 0.67 `fill/9` — на экране, с поправкой на масштаб (2026-10-16); поля 16 у содержимого скролла во всю ширину, плитки уходят за кромки экрана; плитки «Моей волны» нет (2026-10-16). Под ним — промо-слайдер `ShowcasePromo`: свой набор (по три фильма, альбома, книги, исполнителя и станции «Моя волна» вперемешку; 2026-10-13), круг из трёх копий, наклон/масштаб/фон — функция скролла через `visualEffect`; пара ✕/✓ (у альбома — и подпись с аватаром) — только у центральной и вместе, сразу после остановки ленты (2026-10-13; паузу убрали). У альбома пара сверху справа и подпись с аватаром исполнителя (макет `2537:27595`); тап по подписи — экран исполнителя. Исполнитель — круг размером с альбом, подпись одной строкой по центру, пара ✕/✓ по касательной к кругу (центры кнопок на окружности, 26° от верха). Станция — «лепесток» по макету `2688:26198` (`PromoStationCard`): капля цвета станции из палитры «Моя волна 2026» (растр с прогрессивным блюром, кэш по цвету, прогрев под заставкой; поперёк — едва заметный переход в соседний тон, +10° к жёлтому, `PromoStationTint`, 2026-10-16), иллюстрация агента (растры из SVG с внутренними тенями, перекрашены в цвет станции), «Моя волна» + название станции, ✕/✓ внутри карточки; восемь станций (`VibePromoStation.all`), три случайные на запуск, по ✕ — следующая; по тапу играет «Моя волна». ✕ не подменяет айтем, а убирает его из круга: карточка гаснет, ряд схлопывается, правая встаёт в центр; чтобы набор не кончился, сразу за ней в круг встаёт новый айтем того же вида (`ShowcaseCatalog.preparePromoAddition`), убранные не возвращаются. Слот ряда ключуется парой `(копия, id айтема)` (`PromoSlotID`), не номером места: по номеру каждая вставка и ✕ пересоздавали почти все вью, и обложки мигали. Фон — отдельный слой под лентой, как у промо Кинопоиска и Книг (уходит в прозрачность, при оттяге тянется вверх): два непрозрачных слоя из маленького заранее размытого растра (`PromoBackdropRaster`), кроссфейд за пальцем, затемнение — на их сумме. ✕ у «Продолжить читать» и «Смотреть дальше» карточку не подменяет, а убирает: гаснет, как айтем на ✕, слот схлопывается, лента подтягивается (`ShowcaseFeedbackState.removeCard`). ✕ у «Моей Волны» сменяет и иллюстрацию (`VibeArt`), свечение под ней плавно перекрашивается. Хронометраж серии — длина серии сериала (у серий Кинопоиск отдаёт 0); нет её — ни времени, ни размера. Экран тайтла сериала — карусель «Сезоны и Эпизоды» под шапкой (тап — серия в плеере, шеврон — все серии `SeriesEpisodesScreen`, маршрут `EntityRoute.episodes`: под навбаром закреплённые чипсы сезонов «1 сезон, 6 серий», под ними серии выбранного сезона, старт — на сезоне из истории); «Смотреть» продолжает серию из истории, «Скачать» качает первую серию. Загрузка — по сериям (`CollectionItem.episodes`, `CollectionStore.toggleEpisode`); размер — оценка ~10 МБ/мин (`DownloadSize`). «Скачанное» → «Кино» — карточки `medium`: фильм тапом играет, сериал («2 серии, 1,2 ГБ») ведёт на скачанные серии (`SeriesDownloadsScreen`: по сезонам, «Загрузить другие серии» — все серии); полный список — строками с кадром (`StillListRow`). Другая серия в плеере начинается с начала (`MovieInProgress.isSameEpisode`).
- **Профиль** — обычный экран стека активного таба (`AppNavigationState.openProfile`, пуш справа налево; таббар и action bar на профиле спрятаны — уезжают за нижнюю кромку, `HidesBottomChrome`; девменю из профиля — тот же нижний шит, что по Люмену, `homeDevMenu`; навбар — `EntityNavBar` с «назад» без названия; правка пользователя 2026-10-21, прежде — презентация снизу поверх всего с крестиком), по макету `2701:30161`: свечение, герой (баллы, аватар с карандашом, имя), виджеты, островки макета и служебный островок «Дебаг меню» в конце. Аватар, карандаш и баллы левитируют (`ProfileLevitation`): гироскоп опросом внутри `TimelineView` плюс медленный дрейф, амплитуда нарастает за 1.2 с после появления; фильтр — в обычном классе, не в `@State`; Reduce Motion — статично.
- **Диск** — `UserDefaults`/JSON: снимок бара, `WatchHistory`, `CollectionStore` (одна запись на сущность, ключ `<вид>:<id>`; через него — все «нравится», «Позже», «Скачать»), `SearchRecents`. Новые поля — только опциональные. Прогресс на каждом тике не пишем.
- **Кинопоиск** (kinopoisk.dev): ротация ключей по 403, троттлинг, дисковый `MoviePool` (поиск и карточки — сперва из него), батчи, `URLCache`. Кадры — горизонтальные `still` из `/v1.4/image` → `backdrop` → постер (на постере название). Хвост размера CDN — только `ШxВ` (`/300x450`), `/600` — 404. Логотипы TMDB — через прокси `images.weserv.nl` (`TMDBImageProxy`): хост режется DNS. Трейлер в API — страница плеера, поток отдаёт 403: на кавере забандленный клип. Запас поиска фильмов — Kinopoisk API Unofficial (`KinopoiskUnofficialService`, ключи `APIKeys.kinopoiskUnofficial` — `scripts/set-unofficial-keys.sh`, 500/сутки на ключ): включается, когда у kinopoisk.dev кончились все ключи, и только для поиска — витрины и карточки на нём стоили бы в разы больше запросов (нет пачек по id).
- **Прочие API**: Deezer — без ключа (превью 30 с). Google Books — ключ ~1000 запросов/сутки, раз в секунду; текста книги не отдаёт (фрагмент — за Adobe DRM), поэтому читалка показывает аннотацию. Википедия — фото персон.
- **Картинки** — только через `ArtworkLoader`/`ArtworkImage` (`NSCache` + `URLCache`), не `AsyncImage`. Кадр задаёт распорка `Color.clear`, картинка — `scaledToFill` в `overlay` + `clipped()`.
- **Поверхности**: backdrop-блюр — `UIVisualEffectView`, прогрессивный — `VariableBlurView`. Скелетоны — один стиль `PlusSkeleton`, форма как у карточки, заголовки секций — полосами.
- **Поверх всего** (экран фильма и плееры лежат выше корня) — отдельное окно `OverlayWindow` (`windowLevel .alert`, не ключевое, `hitTest` только по своим вью): тост (`ToastCenter.shared.show`, сам висит на `CollectionStore.update` — лайк/«Позже»; ✓ на «Главной») и шеринг. Шеринг — `ShareOverlay` в `OverlayWindow`, `ShareState.shared.present`; кнопки каналов без действий. Окружения корня в нём нет — всё из синглтонов; тап по тосту лайка — `ToastCenter.openCollection` (регистрирует корень). Лайк/«Позже»/скачивание пишут `CollectionStore.lastAddition`, по нему на табе «Моё» 2 с вместо сердца миниатюра добавленного (`CollectionTabPeek.shared`: один объект и один таймер на все копии таббара).
- **Нижний хром** опущен на 4 ниже границы safe area (`PlusChromeMetrics.chromeDrop`, правка пользователя 2026-10-16): подъём над клавиатурой, блюр подложки, поля лент и бар в выдаче считаются от `chromeBottom`, а не от safe area.
- **Раскладка**: слои шире экрана (свечение, шейдер, ряд скелетонов) — оверлеем на распорке, иначе раздувают экран. Инсет под хром — `contentMargins`. Высоты горизонтальных каруселей — явно. Никакого `View.if` вокруг анимируемого: меняет идентичность.

## Грабли

- `Shape` с `EmptyAnimatableData` не интерполируется — SwiftUI держит старое значение всю анимацию.
- `containerRelativeFrame` внутри `ScrollView` уже вычитает его `contentMargins` — не урезать ширину второй раз.
- `scrollPosition(id:anchor:)`: `.center` промахивается на ~3 pt, `.leading` при симметричных `contentMargins` центрирует точно. Стартовый `scrollTo` на появлении срабатывает до раскладки — `.task` с задержкой ~50 мс и транзакцией без анимации.
- Скролл-зависимый слой — `.transaction { $0.animation = nil }`, иначе его подхватит анимация выбора; внутренний `.animation(nil, value:)` перекрывает внешний.
- Подменить список без морфа строк — `.id(значение)` на поддереве.
- Круг из трёх копий на `LazyHStack`: перескок на среднюю копию кадр рисует позицию по оценке, на шаг мимо (мелькает прежняя карточка), а ушедшие за экран слоты держат прежний контент. У промо «Главной» ряды — обычный `HStack`, ключ слота — `(копия, id айтема)`, а не номер места: по номеру ✕ пересоздавал все видимые обложки и они мигали (2026-10-10). Промо Кинопоиска и Книг (один ленивый ряд одинаковых слотов, айтемы на месте не меняются) не моргают — замер 2026-10-08: 30 перескоков без вспышки против 3 из 8 у ленивой «Главной»; оставлены ленивыми. Проверка — `…PromoStep cycle` на видео ([docs/DEBUG.md](docs/DEBUG.md), «Приёмы проверки»).
- `.compositingGroup()` у покадрово меняющегося полупрозрачного стека (затемнение, маска, прозрачность) в покое композитится иначе, чем в движении: фон промо «Главной» в кадр остановки ленты темнел на 8–29 уровней. Сводить в растр — `.drawingGroup()`.
- Запас фильмов (`MoviePool`) идёт на второй круг только через `rewindIfExhausted` по дефицитному блоку: сброс в `markShown` ждал показа всех фильмов, а негодные (без постера или описания) не показываются никогда — «Главная» вставала на моки («Идеальные дни») и жгла запрос на пустой добор (2026-10-16). В сеть — только если `canGrow`.
- Слой фильма показан зумом и на закрытии сжимается в миниатюру-источник: снимать его анимированно в одном апдейте со сменой таба или сброса стека нельзя — источник размонтирован, на iOS 27 UIKit падает по assert (`_morphPreviewFromCurrentState`, крэш TestFlight 2026-10-10: «Позже» → тост → «Моё»). Такие снятия — без анимации (`AppNavigationState.withoutLayerZoom`). Симулятор iOS 26.3 не падает.
- `ArtworkSource.remote(_, fallback:)`: запасной ассет показывается и всё время загрузки, а не только при ошибке. У живого контента fallback не задавать — иначе мелькает чужая моковая обложка вместо скелетона.
- Дубли витрины сверять по произведению, а не по id: Google Books отдаёт одну книгу несколькими томами, Deezer — альбом переизданиями (`ShowcaseCatalog.workKey`).
- Источник зума в карусели — `matchedTransitionSource` у каждой копии, адрес экрана только у текущей (`isCurrent ? route : "…-copy-<слот>"`), а не `if isCurrent {…} else {…}`: смена ветки пересоздаёт карточку посреди свайпа, и она моргает (промо «Главной», Кинопоиска, Книг). Картинка, которую вью грузит в `.task`, берётся из памяти ещё в `init` — иначе новый слайд кадр стоит без неё.
- Начальное значение `@State` с классом в корне (`ActionBarState()` и др.) вычисляется на каждой инициализации `AppRootView` — за запуск их минимум два, лишние умирают. Обработчики в синглтонах (`MusicAudio.onTrackEnd`, `ToastCenter.openCollection`) из `init` не ставить — лишний экземпляр перезапишет их собой, и очередь музыки вставала на конце трека (2026-10-17); только из `body` корня (`onAppear`).
- `.task` без `id` держит замыкание первого монтирования: `@State` в нём живой, а `let`-свойства вью (данные, пришедшие позже) — устаревшие. Нужны свежие — брать из стейта или задать `id`.
- Уведомления клавиатуры iOS шлёт и о чужой: возврат из приложения с поднятой клавиатурой на мгновение раскладывал бар как в поиске. Слушать только свою — `keyboardIsLocalUserInfoKey` (`KeyboardObserver`).
- Скрытый навбар (`.toolbar(.hidden, for: .navigationBar)`) выключает свайп назад от края — он включён обратно делегатом жеста в `App/SwipeBack.swift`.
- Новый imageset инкрементальная сборка не подхватывает — `xcodebuild clean`; проверка: `xcrun --sdk iphonesimulator assetutil --info <app>/Assets.car | grep <имя>`.
- Эмодзи текстом в симуляторе iOS 26.3 — квадраты с «?»: рисовать картинками (`emojiRate*`).
- Флаги-посевы (`-debugSeedContinue`, `-debugActionBar …`) пишут на диск приложения пользователя в его симуляторе. Перед прогоном копировать plist из контейнера (`xcrun simctl get_app_container <udid> com.dima.PlusProtoApp data` → `Library/Preferences/com.dima.PlusProtoApp.plist`), после — вернуть ключи через `xcrun simctl spawn <udid> defaults write <путь без .plist> …`; `defaults export com.dima.PlusProtoApp` через simctl читает не контейнер приложения и даёт пустой файл (2026-10-13).
- Worktree-гард отклоняет составные команды с git (heredoc, `cd … && git`, имена файлов с «git») — разбивать на простые отдельные; длинные правки — скриптом из файла.

## Открытое

**Крупное**
- Настоящий текст книги — сейчас аннотация Google Books. Пути: классика в курируемом каталоге (Викитека, сервиса в коде нет; состав 20–30 произведений не согласован) или приватные API Букмейта/ЛитРес — решение пользователя.
- Второе состояние витрины ([docs/research/figma-screen2.md](docs/research/figma-screen2.md)) — то же представление, карточки переиспользуются.
- Полировка: хаптики (`docs/research/nav-chrome.md` §11, сверка на устройстве), Instruments по скроллу (Animation Hitches), grain орба.

**Ждёт решения пользователя**
- Тайминги-кандидаты: морф action bar 0.32 s `.smooth`, активация таба 0.26 s, плейсхолдер поиска — 4 s на фразу.
- Решения агента по плеерам (2026-10-03): контролы киноплеера гаснут через 4 с; бар остаётся за играющей музыкой во время чтения; круг мини-плеера в читалке разворачивается тапом в пилюлю.
- Тап по «продолжить чтение / смотреть» на витрине «Плюс» — сразу в читалку и плеер или, как сейчас, на экран сущности.
- Цвета текста вне четырёх цветов UI kit: подпись таба `fillSix`, плейсхолдер 30 %, разделитель меты, градиенты подписей витрины, строки альбома.
- На экране фильма и «назад», и «закрыть» (как в макете) — обе снимают экран; какую убрать.
- Сигма ли радиус SwiftUI `.blur(radius:)` — от этого зависят единицы всех блюров; нужен A/B.

**Известные огрехи**
- Даунсемплинга картинок нет: полноразмерные растры в `NSCache` (396 МБ против 346 на моках).
- Трейлер на кавере после возврата из киноплеера — замерший кадр: `onDisappear` ставит паузу, флаг «играет» остаётся.
- «Вписать / заполнить» в киноплеере без анимации: у `AVPlayerLayer` как корневого слоя неявная анимация `videoGravity` выключена.
- Кегль лида тайтла — 24 вместо макетных 32 (`MovieLeadType.size`): у YS Display в строку влезает ~14 символов против ~23 у макетного Yango.
- Сдвиг скролла у экранов, открытых из выдачи, после правок не воспроизводится — проверить руками.
