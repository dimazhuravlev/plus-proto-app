# CLAUDE.md — прототип «Яндекс Плюс»

iOS/SwiftUI дизайн-прототип супераппа «Яндекс Плюс»: у Музыки, Кинопоиска и Книг свои табы с главными витринами, плюс кросс-сервисная витрина «Плюс» и общая коллекция «Моё» (Алисы нет с 2026-10-04). Не продовое приложение: моки + бесплатные публичные API. Пользователь (Дима Журавлёв, продуктовый дизайнер в Яндексе) проектирует здесь опыт взаимодействия. Внутренние разделы сервисов глубже главных не проектируем. Сиблинг `~/Repos/MusicPlayer` — предыдущий прототип, источник архитектуры и компонентов.

Здесь только то, чего не вычитать из кода: правила, вкус пользователя, отвергнутое, грабли и открытое. Что готово — в коде и `git log`. Правда — код: запись, разошедшаяся с ним, — дефект, правь запись.

## Три правила, нарушение которых обесценит работу

1. **Пиксель в пиксель с Figma.** Числа — замером из макета, не на глаз. Значения, которого в макете нет, не заводить.
2. **120 fps.** Не читать размер вью, от которого зависит её же раскладка, — это уже вешало рендер на 100 % CPU; размеры считать от холста 402 pt и констант. Ничего не писать в `@State` на каждом кадре: покадровое — аналитической функцией времени, в покое `TimelineView` уходит из дерева. Жесты — через transform.
3. **Квота Кинопоиска — 200 запросов в сутки на ключ.** Не жечь отладкой. Остаток — `GET /v1.5/token` (квоту не тратит).

## Сборка и верификация

Только Xcode toolchain (Xcode 26.3). Папка репозитория — `plus-proto-app`, таргет/схема — `PlusProtoApp` (ASCII без дефисов, чтобы модуль не стал `plus_proto_app`), bundle `com.dima.PlusProtoApp`, iOS 26.0, Swift 5, вёрстка от ширины 402 pt (iPhone 17 Pro).

```bash
xcodebuild -project PlusProtoApp.xcodeproj -scheme PlusProtoApp -destination 'platform=iOS Simulator,name=iPhone 17 Pro' -configuration Debug build
```

Установка, запуск, отладочные флаги, приёмы проверки — [docs/DEBUG.md](docs/DEBUG.md). У каждого worktree свой хеш в DerivedData: ставить сборку из своего и переустанавливать после каждой сборки — дважды пользователю показали «исправленный» экран со старой сборкой.

**Верификация — руками пользователя, не агентом** (решение 2026-08-25). Агент: собирает проект всегда; один контрольный скриншот (`xcrun simctl io booted screenshot`) — только для новой вёрстки, впервые собранной по макету; в ответе — короткий чек-лист «что посмотреть». Серии скриншотов, пиксельные замеры и прогоны флагов — точечно по фидбеку. Пользователь работает в том же симуляторе, отладочный запуск его сбивает; после запуска с флагами — чистый перезапуск без аргументов. Субагентам симулятор не давать: `simctl … booted` общий. Сомнения снимать замером, а не рассуждением; белый кадр или «глюк simctl» — сперва подозревать баг приложения.

CI ([.github/workflows/build.yml](.github/workflows/build.yml)) — только компиляция на ключах-заглушках.

**TestFlight.** Выгрузка — из Xcode: устройство «Any iOS Device» → Product → Archive → Distribute App → «TestFlight Internal Only» (без ревью; тестеры — участники команды в App Store Connect, до 100) или «App Store Connect» (внешние тестеры и публичная ссылка; первая сборка версии проходит Beta App Review). Таргет — только iPhone (`TARGETED_DEVICE_FAMILY = 1`): вёрстка от 402 pt, на iPad приложение идёт в окне айфона. Подпись под иконкой — «Прото Плюс», запись в App Store Connect — ProtoPlus: чужой бренд на иконке при выпуске с личного аккаунта — первый повод для отказа на ревью внешнего тестирования (2026-10-05). Новое API «с обязательной причиной» (даты файлов, аптайм, место на диске) — в `PlusProtoApp/PrivacyInfo.xcprivacy`, иначе выгрузку отклонят. Ключи API вшиты в сборку и общие на всех тестеров: квота Кинопоиска кончается быстрее, витрины уходят в моки и дисковый запас.

## Конвенции

- Общение, коммиты, UI-копия — на русском. Conventional Commits. Ветки, pull request'ы, условие мержа, код-стайл — [CONTRIBUTING.md](CONTRIBUTING.md). В `main` напрямую не пушим: ветка → PR → зелёная сборка → squash merge. Свой PR — сразу автомерж: в десктопном приложении Claude — инструмент `set_auto_merge` (squash), в терминале — `gh pr merge --auto --squash`. GitHub смержит после зелёной сборки; «не мержь» — оставить открытым. После мержа напомнить пользователю подтянуть `main` в папку, из которой собирает Xcode (`git -C ~/Repos/plus-proto-app pull`): её не трогаем — там работают параллельные сессии.
- «Почему» — сразу: локальное — комментарием у кода; сквозное правило, предпочтение пользователя или отвергнутый вариант — строкой сюда, коротко. Старый лог решений — `git show c8316d9:docs/DECISIONS.md`.
- Токены: только переиспользуемые значения в `DesignSystem/Tokens.swift`; одноразовые градиенты/тени живут локально у компонента («токен ради единственного вызова не заводим»).
- Типографика — только стили UI kit из `DesignSystem/Typography.swift`: `plusText(_:_:)` для YS Text (Title S, Text L/M/S/XS × Semibold/Medium) и `plusHeadline(_:)` для YS Display (Headline XXXL…S, интерлиньяж 100 %); выбор — по доке `PlusTextSize`. Стиль берём по названию из макета; свой кегль, начертание, трекинг или `.font(.custom…)` не заводим. Цвета текста — `fillOne`, `fillFour`, `fillSubtitle`, инверсный чёрный. Заголовки рисует `HeadlineInkRenderer` (базовая линия как в Figma, запас под хвосты): маски по рамке заголовка расширять на `PlusHeadline.inkOutset`.
- Магические числа анимаций — именованными константами в config-enum рядом с компонентом (стиль MusicPlayer: YMTiming, ShareCardDragConfig).
- Файлы добавляются простым созданием на диске (filesystem-synchronized pbxproj) — проект править не нужно.
- `APIKeys.swift` в гитигноре; без него проект не соберётся — копия в `_secrets/`, шаблон — `APIKeys.example.swift` в корне (в сборку не входит). Пустой ключ Кинопоиска — не ошибка: витрина сама идёт на моках (`APIKeysCheck`), сеть не трогается.
- Отладочные флаги из кода не удалять — ими воспроизводятся жалобы. Новый флаг — в таблицу [docs/DEBUG.md](docs/DEBUG.md); хук зовёт тот же код, что настоящий тап.
- Копия: по-русски даже при английском макете; роли — в ед. ч. и с «ё» («Режиссёр»); числа — с русскими склонениями (`CollectionCopy.plural`); однобуквенные предлоги — с неразрывным пробелом.
- **Экран компьютера не трогаем.** Инструменты чтения и управления экраном (computer-use: скриншоты рабочего стола, клики, ввод с клавиатуры, чтение чужого терминала) не запускаем ни автоматически, ни «чтобы посмотреть». Нужен именно такой инструмент — сначала спросить и дождаться явного «да» в чате. Скриншоты iOS-симулятора через `xcrun simctl io booted screenshot` под это правило не попадают — это норма (см. «Сборка и верификация»).

## Вкус пользователя

Обобщено из правок пользователя — применять к новой работе без напоминаний.

**Макет и данные**
- Правка пользователя сильнее макета: сквозные правила для общих компонентов перекрывают варианты из макетов (поле экрана 16; один `EntityNavBar`: кнопки 40, поля 16).
- Просили поменять одно — остальное не трогать: «поставь по центру» не значит «уменьши» (карточки промо Кинопоиска, 2026-10-04).
- Скриншот и макет в одной задаче: источник у каждого элемента свой, со слов пользователя («Моя волна» — по скриншоту, из макета только видео шейдера).
- Адаптация: английский макет — UI по-русски; макет без хрома — держим отношения, ужимаем эластичное (кавер); холст 375 — поля 16, колонка шире; макета нет — собираем из существующих компонентов.
- Не врать о контенте: нет данных — нет элемента; нет логотипа — название текстом. Правдоподобный жанр или хронометраж под живым тайтлом — ложь.
- Мок не подменяет живое: моки — только где данных нет вовсе, ровно текстом макета. Пока живая картинка грузится — скелетон, не моковая обложка.
- Ничего пустого и мёртвого: стартовые наборы (коллекция, «Искали недавно» — пока историю не удалили целиком), моки как фолбэк, кнопка работает до прихода данных. Пустых секций не показываем; не спроектированный раздел — заглушка с названием (`ServiceFilterStub`).
- Одинаковое — одинаково: повторы — общим компонентом без вариантов. «Нравится» и play/pause везде одним движением (`LikeGlyph`, `PlayPauseGlyph`); серые кнопки — одной поверхностью `secondaryButtonSurface` (блюр фона + бордер 0.67 белый 8 %); акцентная кнопка — одна на экран (`accentButtonSurface()`). У сущности одна картинка во всех входах, у пользователя одна аватарка.
- Не переусложнять — это прототип: лишний вход убираем, мелкие огрехи данных допустимы. Демо идёт на симуляторе, поэтому его дефекты чиним в коде.

**Движение**
- Плавность — центральное требование: никаких резких подмен, параметры состояния меняются одной анимацией. Морф — на живых вью без `if/else`; содержимое при морфе разложено по конечному размеру и меняет только прозрачность.
- Ничего не меняется на глазах: витрина собирается под заставкой; бар и «Смотреть дальше» обновляются под выехавшим плеером; выдача поиска публикуется целиком и потом не переставляется. Асинхронное не двигает раскладку: место держится заранее, скелетон повторяет геометрию контента, из кэша — сразу.
- Смена списков и текста — последовательно: старое гаснет ~300 мс, новое проявляется ~300 мс, либо через блюр (`.blurReplace`). Одновременный кроссфейд двух полупрозрачных копий — нет; 150 мс — «слишком резко». Скелетон → контент — не смена списков: карточки встают на его место без кроссфейда, проявляются только обложки и подписи.
- Кривые: движение по экрану и смена на месте — ease-in-out; что едет с клавиатурой — её кривой; уходящее уезжает за кромку экрана, а не гаснет раньше. Несрочное — неспешно.
- Скролл-эффекты — чистая функция скролла (smoothstep без излома) и не зависят от анимаций табов, иначе моргает подложка. В покое блюр шапки не нужен — проявляется по скроллу.
- Жесты: экран идёт за пальцем 1:1 с первого пункта; закрыть легче, чем открыть; закреплённое над лентой тянется за оттягом вчетверо медленнее, с мягким потолком (`ServiceTopNavMotion.pullShift`).
- Анимация не врёт и не навязывается: бегущее троеточие читалось как загрузка; видео — только по тапу и одно; вступление витрины — раз за процесс.
- Reduce Motion — всегда своя ветка (обычно только прозрачность); системная настройка важнее требования к переходу.
- Отклик на нажатие — у всего нажимаемого, даже без пресс-стейта в Фигме: кнопки 0.92, карточки 0.97, строки списков 0.98 (черты не проседают); ячейки островков (профиль, дебаг-меню) — подсветка. Просадка сразу под пальцем, а не после задержки скролла, и у быстрого тапа держится не меньше 0.1 с: `PressScaleButtonStyle` / `.pressScale` (`PressMotion`). Палец на вложенной кнопке («ещё», сердце) достаётся ей.
- Хром не простреливается: тап в зазор между табами достаётся ближайшему табу, в любую точку таббара — не ленте под ним. Зона шире кнопки — `contentShape` под отрицательным отступом, раскладка не едет.
- Хаптика — одна на действие, общим вызовом: табы и фильтры — `TabBarMotion.tapHaptic()`, кнопки плеера — impact light, перемотка — лёгкая трещотка, ✓ — success, ✕ — medium.
- Блюр — один, нижним слоем, прогрессивный и только по контенту: начинается там, где контент заходит под хром. Навигация витрин, скрим «Плюса», профиль, закреплённые чипсы — блюр без затемнения.

## Отвергнуто — не повторять

- Морф мини-плеера в полноэкранный — плееры выезжают снизу через презентер, без масштаба и прозрачности.
- Закрытие плеера по резине скролла или своим UIKit-паном — лента уезжала раньше экрана; есть `PullToDismiss`.
- «Похожее» подменой `coveredRoute` или `NavigationStack` внутри `fullScreenCover` — свайп назад закрывал весь слой; есть вложенные `CoveredEntityScreen`.
- Слои поиска поверх всего (прятали таббар), в оверлее корня (мелькала витрина), только в корне стека (с альбома слой уходил под пуш).
- Одновременный кроссфейд списков при смене фильтра; переезд капсулы между чипсами второго уровня — капсула гаснет и зажигается на месте.
- Окно ротации витрины и первый элемент выдачи — витрина повторялась из запуска в запуск. Лента промо из 200 повторов — открывалась у края; есть круг из трёх копий.
- Срезанные хвосты YS Display лечить отступом, `baselineOffset` или натуральным интерлиньяжем — ломает раскладку и «Й/Ё»; есть `HeadlineInkRenderer`.
- Из MusicPlayer не берём: гиро-параллакс; `ScrollOffsetPreferenceKey` (перерисовывает хром на каждом кадре); покадровый lerp и накопление угла в `@State`; пресс на `DragGesture`. Блюр на каждый глиф «волны» текста вешал главный поток.
- Отладочный дамп сырых полей API на экране — сжигал квоту Кинопоиска.
- Источники: TMDB API (DNS → 127.0.0.1), iTunes Search (пусто), трейлеры (YouTube; HLS Кинопоиска подписан — 403), поиск персон Кинопоиска (однофамильцы без фото); Google Books — тематический поиск по-русски (мусор) и `inauthor:` (ноль), Gutendex, Internet Archive; Deezer `/artist/{id}/top` из РФ пуст, поиск артиста по имени находит тёзок.

## Архитектура

- **Каркас — от MusicPlayer**: свитч `AppTab` + `NavigationStack` на таб, хром (таббар, action bar) в `ZStack` вне стеков, env-объекты из корня, `@Observable`. Вью читает состояние через `@Environment` сама: параметр и ручной `Binding` зависимость не регистрируют.
- **`AppNavigationState`**: таб, пути, слои (`coveredRoute`/`coveredPath`), профиль. Табы переключаются мгновенно. Поп — `removeLast()`: подмена пути убивает обратный зум. Тап по активному табу — к корню, на корне — к началу экрана.
- **Экраны**: фильм — `fullScreenCover` над хромом, дальше — вложенные `CoveredEntityScreen` со своим `BottomChrome`; альбом, плейлист, книга, персоны — пуш с хромом. Переходы — через `navigation.open`, не `NavigationLink`. Зум — `.zoom` с `sourceID` = `EntityRoute`; источник — только миниатюра `showcaseThumbnail()`, и её рисунок обязан умещаться в собственный кадр (система режет портлет по кадру); сдвиг — `padding`, не `offset`.
- **Плееры** — только через `ContentPlayerPresenter` (UIKit-презентация с верхнего контроллера поверх любых слоёв: музыка `.overFullScreen`, кино и читалка `.fullScreen`); открывают их `ActionBarState.watch/read`. Свой `fullScreenCover` под плеер не заводить. Под `.fullScreen` экраны уходят с окна и их `.task` перезапускаются — задачи должны быть идемпотентны. Приложение заперто в портрете: альбомный плеер нарисован повёрнутым холстом.
- **Кто включает плеер**: кнопки экранов сущностей («Слушать», «Смотреть», «Читать»); переход по карточке — нет. Сразу играет то, у чего нет своего экрана: «Моя Волна», трек в полной выдаче и в коллекции, карточки «Смотреть дальше» (киноплеер с места остановки). Плейлисты отовсюду открывают свой экран — `PlaylistScreen`, по конструкции альбома.
- **Action bar = «продолжить»**: режим задаёт последний запущенный контент, а не таб; снимок на диске. Музыку глушат только play/pause и запуск кино. Беззвучное видео — `AVAudioSession .ambient`.
- **Клавиатура**: корень, корень стека, каждый пуш и слой — `ignoresSafeArea(.keyboard)`; отступ хрома считает `KeyboardObserver`; бар поднимается по `keyboard.isUp` — второе поле ввода тоже раскроет бар.
- **Поиск**: слои — в стеке экрана, где поиск открыт, соседями в `ZStack` (в `.overlay` backdrop-блюр видит пустоту); `SearchNavigationSync` — на корне и на экранах слоя. Возврат из карточки — в выдачу без клавиатуры.
- **Две версии выдачи** — карусели по разделам и сетка вперемешку (`SearchMosaicView`); вид выбирается в дебаг-меню профиля (`SearchResultsStyle`, ключ `searchResultsStyle`) и меняет и нулевое состояние: у сетки «Искали недавно» тоже сеткой, вся история сразу, без полного списка, в конце — «Удалить историю поиска» (`SearchRecentsMosaicView`). Порядок сетки — `SearchState.mixed`: в первом ряду лучшее из каждого раздела, чьё название отвечает запросу, дальше слияние разделов по весу совпадения со штрафом за повтор раздела подряд; порядок внутри раздела не меняется. Сетка шире каруселей: в ней плейлисты и создатели лучших работ — режиссёры и писатели с фото, сразу за своими фильмами и книгами, с долей их веса. Сетка дописывается порциями только в конец, а когда кончается выдача обзора — один добор полными выдачами трёх разделов.
- **Витрины**: свежий случайный набор на каждый холодный запуск, стабильный внутри процесса (зёрна — `ShowcaseRotation`); позиция промо помнится на сессию. Каталоги живут в корне (`AppRootView`) — экраны табов размонтируются на каждом переключении. Запуск под заставкой, пока витрина не соберётся (данные + обложки, потолок 6 с). Витрина «Плюс» — модель `{заголовок, [блоки], фон}`, `ForEach` по слоту, а не по контенту.
- **Диск** — `UserDefaults`/JSON: снимок бара, `WatchHistory`, `CollectionStore` (одна запись на сущность, ключ `<вид>:<id>`; через него — все «нравится», «Позже», «Скачать»), `SearchRecents`. Новые поля — только опциональные. Прогресс на каждом тике не пишем.
- **Кинопоиск** (kinopoisk.dev): ротация ключей по 403, троттлинг, дисковый `MoviePool` (поиск и карточки — сперва из него), батчи, `URLCache`. Кадры — горизонтальные `still` из `/v1.4/image` → `backdrop` → постер (на постере название). Хвост размера CDN — только `ШxВ` (`/300x450`), `/600` — 404. Логотипы TMDB — через прокси `images.weserv.nl` (`TMDBImageProxy`): хост режется DNS. Трейлер в API — страница плеера, поток отдаёт 403: на кавере забандленный клип.
- **Прочие API**: Deezer — без ключа (превью 30 с). Google Books — ключ ~1000 запросов/сутки, раз в секунду; текста книги не отдаёт (фрагмент — за Adobe DRM), поэтому читалка показывает аннотацию. Википедия — фото персон.
- **Картинки** — только через `ArtworkLoader`/`ArtworkImage` (`NSCache` + `URLCache`), не `AsyncImage`. Кадр задаёт распорка `Color.clear`, картинка — `scaledToFill` в `overlay` + `clipped()`.
- **Поверхности**: backdrop-блюр — `UIVisualEffectView`, прогрессивный — `VariableBlurView`. Скелетоны — один стиль `PlusSkeleton`, форма как у карточки, заголовки секций — полосами.
- **Раскладка**: слои шире экрана (свечение, шейдер, ряд скелетонов) — оверлеем на распорке, иначе раздувают экран. Инсет под хром — `contentMargins`. Высоты горизонтальных каруселей — явно. Никакого `View.if` вокруг анимируемого: меняет идентичность.

## Грабли

- `Shape` с `EmptyAnimatableData` не интерполируется — SwiftUI держит старое значение всю анимацию.
- `containerRelativeFrame` внутри `ScrollView` уже вычитает его `contentMargins` — не урезать ширину второй раз.
- `scrollPosition(id:anchor:)`: `.center` промахивается на ~3 pt, `.leading` при симметричных `contentMargins` центрирует точно. Стартовый `scrollTo` на появлении срабатывает до раскладки — `.task` с задержкой ~50 мс и транзакцией без анимации.
- Скролл-зависимый слой — `.transaction { $0.animation = nil }`, иначе его подхватит анимация выбора; внутренний `.animation(nil, value:)` перекрывает внешний.
- Подменить список без морфа строк — `.id(значение)` на поддереве.
- Новый imageset инкрементальная сборка не подхватывает — `xcodebuild clean`; проверка: `xcrun --sdk iphonesimulator assetutil --info <app>/Assets.car | grep <имя>`.
- Эмодзи текстом в симуляторе iOS 26.3 — квадраты с «?»: рисовать картинками (`emojiRate*`).
- Worktree-гард отклоняет составные команды с git (heredoc, `cd … && git`, имена файлов с «git») — разбивать на простые отдельные; длинные правки — скриптом из файла.

## Открытое

**Крупное**
- Настоящий текст книги — сейчас аннотация Google Books. Пути: классика в курируемом каталоге (Викитека, сервиса в коде нет; состав 20–30 произведений не согласован) или приватные API Букмейта/ЛитРес — решение пользователя.
- Живой текст заголовка витрины: врезки живые, слова моковые; позиции врезок расставлены под конкретную разбивку строк — нужен пересчёт. Стиль заголовка 32/36 вне шкалы UI kit — перевести на L 28 или XL 36.
- Второе состояние витрины ([docs/research/figma-screen2.md](docs/research/figma-screen2.md)) — то же представление, карточки переиспользуются.
- Полировка: хаптики (`docs/research/nav-chrome.md` §11, сверка на устройстве), Instruments по скроллу (Animation Hitches), grain орба.

**Ждёт решения пользователя**
- Тайминги-кандидаты: морф action bar 0.32 s `.smooth`, активация таба 0.26 s, плейсхолдер поиска — 4 s на фразу.
- Решения агента по плеерам (2026-10-03): контролы киноплеера гаснут через 4 с; бар остаётся за играющей музыкой во время чтения; круг мини-плеера в читалке разворачивается тапом в пилюлю.
- Тап по «продолжить чтение / смотреть» на витрине «Плюс» — сразу в читалку и плеер или, как сейчас, на экран сущности.
- Цвета текста вне четырёх цветов UI kit: подпись таба `fillSix`, плейсхолдер 30 %, разделитель меты, градиенты подписей витрины, строки альбома.
- На экране фильма и «назад», и «закрыть» (как в макете) — обе снимают экран; какую убрать.
- Сигма ли радиус SwiftUI `.blur(radius:)` — от этого зависят единицы всех блюров; нужен A/B.

**Известные огрехи**
- Даунсемплинга картинок нет: полноразмерные растры в `NSCache` (396 МБ против 346 на моках).
- `ActionBarState.debugBook` — чужая обложка (`mockChipBookCover` вместо `mockBookTechno`).
- Трейлер на кавере после возврата из киноплеера — замерший кадр: `onDisappear` ставит паузу, флаг «играет» остаётся.
- «Вписать / заполнить» в киноплеере без анимации: у `AVPlayerLayer` как корневого слоя неявная анимация `videoGravity` выключена.
- Кегль лида тайтла — 24 вместо макетных 32 (`MovieLeadType.size`): у YS Display в строку влезает ~14 символов против ~23 у макетного Yango.
- Сдвиг скролла у экранов, открытых из выдачи, после правок не воспроизводится — проверить руками.
