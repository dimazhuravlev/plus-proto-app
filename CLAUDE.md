## Сборка и верификация

Проект собирается только через Xcode toolchain (Xcode 26.3). Папка репозитория — `plus-proto-app`, Xcode-таргет/схема — `PlusProtoApp` (ASCII без дефисов, чтобы имя Swift-модуля не превращалось в `plus_proto_app`):

```bash
xcodebuild -project PlusProtoApp.xcodeproj -scheme PlusProtoApp -destination 'platform=iOS Simulator,name=iPhone 17 Pro' -configuration Debug build
```

Запуск: `xcrun simctl install booted <DerivedData>/.../PlusProtoApp.app && xcrun simctl launch booted com.dima.PlusProtoApp`. Внимание: у каждого worktree свой хеш пути в DerivedData — ставить сборку из своего.

**Верификация — руками пользователя, не агентом** (решение 2026-08-25). Агент: собирает проект всегда; один контрольный скриншот (`xcrun simctl io booted screenshot`) — только для новой вёрстки, впервые собранной по макету; в ответе — короткий чек-лист «что посмотреть». Серии скриншотов по состояниям, пиксельные замеры и прогоны дебаг-флагов — не по умолчанию, а точечно по фидбеку. Дебаг-флаги из кода не удалять — ими воспроизводятся жалобы. Если агент запускал приложение с флагами — в конце обязателен чистый перезапуск без аргументов, чтобы симулятор остался пользователю.

## Конвенции

- Общение, коммиты, UI-копия — на русском. Conventional Commits.
- Ветки, pull request'ы, условие мержа и код-стайл — [CONTRIBUTING.md](CONTRIBUTING.md). В `main` напрямую не пушим: ветка → PR → зелёная сборка → squash merge. Запись в `docs/DECISIONS.md`, разошедшаяся с кодом, — дефект: правда всегда код.
- Токены: только переиспользуемые значения в `DesignSystem/Tokens.swift`; одноразовые градиенты/тени живут локально у компонента («токен ради единственного вызова не заводим»).
- Типографика — только стили UI kit из `DesignSystem/Typography.swift`: `plusText(_:_:)` для YS Text (Title S, Text L/M/S/XS × Semibold/Medium) и `plusHeadline(_:)` для YS Display (Headline XXXL…S, интерлиньяж 100 %). Стиль берём по названию из макета; свой кегль, начертание, трекинг или `.font(.custom…)` не заводим. Цвета текста — `fillOne`, `fillFour`, `fillSubtitle`, инверсный чёрный.
- Файлы добавляются простым созданием на диске (filesystem-synchronized pbxproj) — проект править не нужно.
- `APIKeys.swift` в гитигноре; без него проект не соберётся — копия в `_secrets/`, шаблон для новых участников — `APIKeys.example.swift` в корне (в сборку не входит: синхронизирована только папка `PlusProtoApp`). Пустой ключ Кинопоиска — не ошибка: витрина сама идёт на моках (`APIKeysCheck`), сеть не трогается.
- Живые данные витрины: `-debugMockFeed` — прогон на моках без сети (для сверки с макетом), `-debugFrozenFeed` — зафиксировать зерно выборки, чтобы витрина повторилась (окна ротации больше нет: контент случайный на каждый холодный запуск).
- Запуск идёт под заставкой, пока витрина не соберётся (данные + обложки, потолок 6с). Прогонам, которые снимают кадры по таймеру от старта процесса, нужен `-debugNoSplash` — иначе вся раскладка сдвигается.
- Плеер включают только кнопки экранов сущностей («Слушать», «Смотреть», «Читать»); переход по карточке его не запускает. Нажать кнопку в прогоне — `-debugTapPlay 1`.
- «Смотреть», «Читать» и чипы action bar открывают киноплеер и читалку на весь экран — через `ActionBarState.watch/read` и `ContentPlayerPresenter` (UIKit-презентация с верхнего контроллера, поверх любых слоёв). Свой `fullScreenCover` под плеер не заводить. Приложение заперто в портрете: альбомный макет плеера нарисован повёрнутым холстом.
- Магические числа анимаций — именованными константами в config-enum рядом с компонентом (стиль MusicPlayer: YMTiming, ShareCardDragConfig).
- **Экран компьютера не трогаем.** Инструменты чтения и управления экраном (computer-use: скриншоты рабочего стола, клики, ввод с клавиатуры, чтение чужого терминала) не запускаем ни автоматически, ни «чтобы посмотреть». Нужен именно такой инструмент — сначала спросить и дождаться явного «да» в чате. Скриншоты iOS-симулятора через `xcrun simctl io booted screenshot` под это правило не попадают — это норма (см. «Сборка и верификация»).
