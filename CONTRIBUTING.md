# Правила работы с репозиторием

Обязательны к соблюдению. Конвенции проекта, которых здесь нет, — в [CLAUDE.md](CLAUDE.md);
состояние дел и приёмы проверки — в [docs/HANDOFF.md](docs/HANDOFF.md).

## Ветки и pull request

`main` всегда собирается. Изменения попадают в него только через pull request.

```bash
git checkout main && git pull
git checkout -b feat/<кратко-латиницей>
# правки, локальная сборка, коммиты
git push -u origin feat/<кратко-латиницей>
gh pr create --fill --base main
```

Префиксы веток: `feat/`, `fix/`, `docs/`, `refactor/`, `ci/`.

**Условие мержа: зелёная проверка сборки и отсутствие конфликтов с `main`.** Больше ничего
не требуется — ни апрува, ни ручного прогона в симуляторе перед кнопкой. Способ мержа —
Squash and merge, ветка после мержа удаляется.

Ветка отстала от `main` или конфликтует — обновить локально, разрешить, пересобрать:

```bash
git checkout main && git pull
git checkout <ветка> && git merge main
```

## Коммиты

Conventional Commits, русский язык. Заголовок — что стало, в повелительном или
результативном наклонении, до 72 символов. Тело — **почему** так, а не перечень
изменённых файлов. Трейлер `Co-Authored-By` для агентских коммитов обязателен.

## Код

- Swift 5, SwiftUI, деплой-таргет iOS 26.0. Вёрстка считается от ширины 402 pt.
- Комментарий объясняет **почему**, а не что делает строка. Неочевидное решение без
  комментария считается недокументированным.
- Переиспользуемые значения — в `DesignSystem/Tokens.swift`. Одноразовый градиент, тень
  или отступ живут локальной константой у компонента: токен ради единственного вызова
  не заводится.
- Числа анимаций — именованными константами в config-enum рядом с компонентом
  (`ActionBarMotion`, `SearchPullConfig`, `ShowcaseMotion`).
- Новые файлы создаются на диске внутри `PlusProtoApp/`: папка синхронизирована с таргетом,
  `.xcodeproj` править не нужно. Любой `.swift` внутри неё попадает в сборку.
- Отладочные флаги из кода не удаляются — ими воспроизводятся дефекты. Новый флаг
  добавляется в таблицу [docs/HANDOFF.md](docs/HANDOFF.md), раздел 7.
- UI-копия и пользовательские тексты — на русском.

## Лог решений

**Каждое принятое решение записывается в [docs/DECISIONS.md](docs/DECISIONS.md) в тот же
день, вместе с причиной.** Это обязательная часть работы, а не документация постфактум:
без «почему» решение переделывается по кругу.

Формат — `дата · решение · почему · статус` (✅ принято / ⏳ предложено / ❌ отклонено),
новые записи сверху нужного раздела, ничего не удаляется. Файл склеивается `merge=union`
(см. [.gitattributes](.gitattributes)): параллельные записи не конфликтуют.

Запись, разошедшаяся с кодом, — дефект. Правда — код; лог приводится к нему, а не наоборот.

## Проверка

CI ([.github/workflows/build.yml](.github/workflows/build.yml)) собирает каждый PR на
Xcode 26.3 с ключами-заглушками. Это проверка компиляции, и только её.

Вёрстку, анимации и поведение проверяет человек в симуляторе — агент собирает проект
всегда, скриншоты и прогоны с флагами делает точечно, по запросу. Подробнее — CLAUDE.md,
раздел «Сборка и верификация».

## Не коммитится

`PlusProtoApp/APIKeys.swift`, `_secrets/`, `DerivedData/`, `xcuserdata/`, `.DS_Store`,
артефакты прогонов и скриншоты. Секреты в CI не нужны: сборка идёт на пустых ключах.
