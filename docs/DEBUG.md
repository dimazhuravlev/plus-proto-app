# Отладка: флаги запуска и приёмы проверки

Справочник на случай, когда надо воспроизвести жалобу или снять состояние без тапов.
Правила работы и сборка — в [CLAUDE.md](../CLAUDE.md). По умолчанию прогонов с флагами
не делаем, проверяет пользователь (CLAUDE.md, «Верификация»). Если агент запускал
приложение с флагами, в конце — чистый перезапуск без аргументов.

## Запуск

```bash
APP="$(xcodebuild -project PlusProtoApp.xcodeproj -scheme PlusProtoApp -destination 'platform=iOS Simulator,name=iPhone 17 Pro' -showBuildSettings 2>/dev/null | awk '/ BUILT_PRODUCTS_DIR = /{print $3}')/PlusProtoApp.app"
xcrun simctl terminate booted com.dima.PlusProtoApp
xcrun simctl install booted "$APP"
xcrun simctl launch booted com.dima.PlusProtoApp -debugMockFeed -debugTab kinopoisk
sleep 3 && xcrun simctl io booted screenshot /tmp/plus.png
```

Путь к `.app` берём из `BUILT_PRODUCTS_DIR`, а не маской по DerivedData: у каждого
worktree свой хеш, маска подхватит чужую сборку.

Окружение: Xcode 26.3, iPhone 17 Pro (iOS 26.0), экран 402×874 pt, скриншот 1206×2622 (×3).
Ориентиры для замеров (pt от низа экрана): ряд табов 34…100, action bar 104…164,
поля экрана 24 (в фокусе 16).

## Два вида флагов

Голые (`-debugMockFeed`) разбирает `PlusProtoAppApp.parseDebugLaunchArguments` — он же
сбрасывает их ключи, если в этом запуске флаг не передан, иначе после прогона обычный
Run из Xcode остаётся в отладочном режиме.

Остальные (`-debugTapPlay 1`, `-debugBarProbe 1`, `-debugOpenSimilar 2`) читаются прямо из
`UserDefaults`, то есть приезжают через argument domain. Он разбирает аргументы парами
«`-ключ` значение»: **значение обязательно**, голый флаг в конце строки молча теряется.
Ключ живёт до конца процесса.

Новый флаг: либо регистрировать в `parseDebugLaunchArguments` в обоих местах (сброс и
разбор), либо читать в форме со значением. И добавить строку в таблицу ниже.

## Флаги

| Флаг | Что делает |
|---|---|
| `-debugTab <plus\|music\|kinopoisk\|books\|collection>` | стартовый таб |
| `-debugActionBar <search\|music\|movie\|book>` | режим бара |
| `-debugSearchFocus` | фокус в поиске через 0.8с (поднимает клавиатуру) |
| `-debugMorphCycle` | прогон четырёх режимов по кругу каждые 1.6с — для записи морфа |
| `-debugBarProbe 1` | надпись над правой зоной action bar: режим, заказанная ширина → отрисованная. Отвечает, разъехались ли состояние и геометрия |
| `-debugScrollTo <pt>` | стартовая прокрутка витрины |
| `-debugTapBlock <1…6>` | повторяет тап по n-й карточке витрины (через 1,5 с после прихода живых данных) |
| `-debugSearchQuery <текст>` | набрать запрос без клавиатуры: фокус и текст через 1с |
| `-debugSearchDelay <сек>` | отодвинуть фокус `-debugSearchQuery` — поиск, открытый с запушенного экрана, должен включиться после того, как пуш доехал |
| `-debugSearchCycle` | фокус и выход из поиска по кругу каждые 3с — снять на видео уход затемнения. Выход — как у «Назад» (`exitSearch`), тем же мягким уходом клавиатуры, что скролл выдачи (`KeyboardObserver.dismissSmoothly`) |
| `-debugExpandSection <раздел>` | раскрыть полную выдачу раздела (`music`, `movies`, `books`), когда пришла выдача; в паре с `-debugSearchQuery` |
| `-debugSearchFilter <n>` | в полной выдаче музыки выбрать n-й фильтр (0 — «Вся музыка», 1 — исполнители, 2 — альбомы, 3 — плейлисты) через 0.5с после прихода выдачи; в паре с `-debugSearchQuery … -debugExpandSection music`. В сетке — n-й чипс: 0 — «Всё», дальше разделы, в которых что-то нашлось |
| `-searchResultsStyle <carousels\|masonry>` | вид выдачи поиска на один запуск — поверх выбора в дебаг-меню профиля. Без префикса debug: это ключ самой настройки, аргумент подменяет её только в этом процессе. Сетка: `-searchResultsStyle masonry -debugSearchQuery дюна` |
| `-debugTapSearchHit <n>` | тап по первой карточке n-й непустой секции выдачи (1 — первая по порядку выдачи, он ранжируется по запросу), один раз за запуск; в паре с `-debugSearchQuery` и `-debugCloseEntity` даёт круг «ушёл — вернулся» — на возврате выдача без клавиатуры, таббара нет |
| `-debugOpenHistory 1` | открыть полный список истории «Искали недавно», когда на экране нулевое состояние поиска; в паре с `-debugSearchFocus` |
| `-debugResetSearchRecents 1` | начать с пустой истории «Искали недавно» — в карусели один стартовый набор (история на диске стирается, стёртый кнопкой «Удалить историю» набор возвращается) |
| `-debugRetapTab <сек>` | через столько секунд — тап по уже активному табу: поп до корня или, на корне, скролл к началу. С `-debugSearchQuery … -debugTapSearchHit 1` проверяет «из карточки поиска — к контенту таба» |
| `-debugCinemaScroll <pt>` | стартовая прокрутка главной Кинопоиска, когда лента собралась (через 1.5 с) — нижние карусели скриншотом. Пара к `-debugTab kinopoisk` |
| `-debugPromoStep <back\|next\|n>` | через 3с пролистать промоблок главной Кинопоиска: `back` с первого слайда — последний набора (проверка круга). Пара к `-debugTab kinopoisk` |
| `-debugResetWatchHistory 1` | начать с пустой «Смотреть дальше» на главной Кинопоиска (история просмотра на диске стирается) |
| `-debugProfile 1` | через 1.5 с открыть экран профиля — как тап по аватарке навигации витрин |
| `-debugResetCollection 1` | начать коллекцию «Моё» со стартового набора (сохранённая на диске стирается) |
| `-debugCollectionList <movie\|book\|track\|artist\|album\|playlist>` | через 1.5 с открыть полный список коллекции на этом фильтре (полка «Любимое»). Пара к `-debugTab collection` |
| `-debugShowcaseDismiss <n>` | ✕ у n-го блока витрины (1 — кино, 2 — альбом, 3 — книга, 4 — «Моя Волна») через 6 с и ещё раз через 3 с: смена айтема на новый — первая из заготовки, вторая тоже |
| `-debugShowcaseDone <n>` | ✓ у n-го блока витрины через 6 с: кнопка белеет, через 800 мс пара гаснет |
| `-debugMockFeed` | витрина на моках, без сети — для сверки вёрстки с макетом. Включается сама, если `APIKeys.kinopoisk` пуст |
| `-debugFrozenFeed` | зафиксировать зерно выборки, чтобы витрина повторилась. Окна ротации нет: контент случайный на каждый холодный запуск |
| `-debugResetMoviePool` | опустошить запас фильмов на диске — иначе первый запуск после установки не проверить, не переустанавливая приложение |
| `-debugNoSplash` | без заставки. Нужен прогонам, которые снимают кадры по таймеру от старта процесса: иначе заставка сдвигает всю раскладку |

| `-debugHitProbe` | через 5с печатает в консоль дерево доступности с кадрами: что нажимается и где |
| `-debugHitSweep <x>` | через 5с проходит вертикаль `x` шагом 8 pt и печатает, какому UIKit-вью достаётся касание (с кадрами и размером содержимого скроллов). | `-debugLayerProbe` | вместе с `-debugCloseEntity` — через 0.4с после закрытия экрана печатает дерево `UIView`: живая вью на экране или системная копия поверх неё |

| `-debugTapCover` | тап по каверу тайтла через 4с и повторный через 6с — снять оба состояния. **Не ставить последним аргументом**: голый флаг в конце строки теряется |

| `-debugTapCycle 1` | переключение табов по кругу, два круга и стоп — для записи анимации таббара |
| `-debugSystemPress 1` | нажатие — на одном системном `isPressed`, без распознавателя касания (`PressFeedback.swift`): карточки снова проседают после задержки скролла. Сравнить с мгновенным откликом или исключить распознаватель, если тап или скролл ведут себя странно |
| `-debugPlayCycle` | play/pause по кругу каждые 4с — для съёмки инерции вращения |

## Приёмы проверки

На каждом из них уже обожглись:

- **Отладочные `.task` успевают отработать под заставкой** — задержки в них давать
  с запасом на холодный старт (3–5с), иначе состояние откроется и закроется до первого
  видимого кадра.
- **Отладочная задача на витрине не переживёт пуш.** `NavigationStack` размонтирует корень
  под запушенным экраном, `.task` отменяется вместе с ожиданием. Всё, что должно случиться
  после перехода, вешать на сам экран назначения.
- **Живая вью или системная копия поверх неё — смотреть дампом `UIView`** (`-debugLayerProbe`:
  классы, кадры, альфа, клип). Скриншот на это не отвечает: зум-переход показывает
  источник портлетом, обрезанным по кадру источника, прячет сам источник (`hidden=Y`)
  и снимает морф через 0.7–2с после анимации.
- **Что нажимается и где — дампом доступности** (`-debugHitProbe`), а не глазами: у каждой
  кнопки виден реальный прямоугольник в координатах экрана. Так поймана раздутая хит-зона
  видеокадра (359×156 против видимых 277×156). Кадр повёрнутого элемента в дампе — AABB,
  он всегда чуть больше видимого силуэта.
- **Анимации разбирать покадрово**: `xcrun simctl io booted recordVideo` → `ffmpeg -vf fps=60`
  → замер координат питоном с PIL. Но `recordVideo` пишет только изменившиеся кадры, и PTS
  не соответствует настенному времени (15 с записи могут дать 2.3 с видео): на вопрос
  «сработало или нет» надёжнее отвечают статические скриншоты по таймеру.
- **Наклонные элементы сверять замером пикселей, а не глазом.** Полоса под углом 5° на кропе
  читается как две — час ушёл на поиск несуществующего дубля.
- **Эмодзи в симуляторе iOS 26.3 — квадраты с «?»**: сломан эмодзи-шрифт самого симулятора
  (так же рисуют голый `UILabel` и Safari). Поэтому блоки оценки рисуют эмодзи картинками
  (`emojiRate*`); эмодзи текстом в новых местах сломаются так же.
