## Продукт / дизайн

- 2026-08-22 · **Два экрана витрины в Фигме — это ОДИН экран в разных состояниях** (grill Q12), а не два разных экрана. Витрина «Плюс» задумана динамической: под событие и контекст меняются **заголовок, набор блоков, их содержание и фон**. Архитектура сразу закладывается под это: модель витрины = `{заголовок, [блоки], источник фона}` · ✅
  - **Сейчас НЕ проектируем**: порядок блоков и динамику верхнего заголовка. Реализуем один статичный состав (экран 1 из макета), но на модели, которая позже примет разные состояния.

- 2026-08-22 · **Таб «Алиса» — пустая заглушка**, как и остальные сервисные табы · ✅
- 2026-08-22 · **Минимальная iOS — 26** (не 18.5 как в MusicPlayer) · новейшие SwiftUI API и лучший контроль над производительностью скролла/120fps; обратная совместимость прототипу не нужна. Следствие: код из MusicPlayer переносится свободно, но можно использовать и новые API · ✅
- 2026-08-22 · **Видео для карточки «продолжить смотреть» — забандленные клипы** (grill Q11). Исходники указаны пользователем: `~/Yandex/video clips/{fallen angels,yura,movie-short}.mov`. **Оптимизированы и лежат в `_assets/videos/`**: H.264 High, ширина 1080, 30 fps, CRF 24, звук удалён, `+faststart` (moov в начале — старт без полной загрузки). Итог: **167,7 МБ → 3,58 МБ** (fallen-angels 0,76 / yura 0,50 / movie-short 2,32 МБ) · сетевого риска на демо ноль, мгновенный старт; прямых трейлеров-mp4 в природе не осталось · ✅
  - Для плеера: `AVQueuePlayer` + `AVPlayerLooper`, `isMuted = true`, **обязательно `AVAudioSession` категории `.ambient`** — иначе тихое видео в ленте оборвёт музыку Deezer.
- 2026-08-22 · **Книги: три источника вместо одного** (grill Q11; решение по составу — за мной). Аналога Deezer, где мета+контент из одного места, для книг не существует:
  - **Обложки → Google covers CDN**, без ключа, `fife=w1600` → 1600×2476 (требование пользователя: «качественный кавер нормального размера, не микроминиатюры»)
  - **Метаданные → Google Books API с ключом**, `langRestrict=ru` (требование: вся мета на русском)
  - **Текст произведения → ru.wikisource**, без ключа (требование: части произведения на русском — для виджета «продолжить чтение» и будущего книго-плеера)
  - **Связующее звено — курируемый каталог** (по образцу `DeezerMusicScope.swift`): зашиваем 20–30 книг, у каждой `googleVolumeId` + путь главы в Викитеке. Иначе обложка, мета и текст рискуют относиться к разным изданиям — автоматического сопоставления между Google Books и Викитекой нет.
  - Открытая опция (не берём без отдельного решения): у **Букмейта** и **ЛитРес** есть живые недокументированные API без авторизации с отличными русскими данными, обложками 1500×2250 и цитатами из книг. Это приватные API, разрешения в ToS нет — для внутреннего прототипа технически годится, но решение за пользователем.
- 2026-08-22 · **Книги: обложки — Google covers CDN (без ключа), текст — Викитека (без ключа)** (проверено запросами):
  - **Обложки**: `books.google.com/books/publisher/content?id={id}&printsec=frontcover&img=1&zoom=1&fife=w1600` → **1600×2476**, ключ НЕ нужен (CDN не попадает под квоту API). Проверено: `zoom=1`→128×198, `zoom=3`→575×889, `fife=w1600`→1600×2476. Нужен фолбэк: у части изданий вместо обложки заглушка 1269 байт.
  - **Текст книги для карточки «продолжить чтение»**: `ru.wikisource.org/w/api.php?action=parse&page=<...>&prop=text` — отдаёт **настоящий русский текст**. Проверено на «Преступлении и наказании»: 16 561 символ главы. Обязателен осмысленный `User-Agent`, иначе ловится 429. Пути глав резолвить заранее (`list=allpages&apprefix=`) и зашивать — в рантайме 1 запрос на книгу. `prop=extracts` не работает (TextExtracts на Wikisource выключен).
  - **Метаданные**: Google Books API **без ключа больше не работает** — квота обнулена (`quota_limit_value: 0`, `RESOURCE_EXHAUSTED`), не «исчерпана», а именно ноль. Нужен бесплатный ключ (~1000/сутки) либо фолбэк на Open Library (без ключа, но обложки максимум **386×500** — для полуэкранной книги в макете мало).
  - Отклонено: **Gutendex** — всего 9 русских книг, половина аудио-заглушки; **Internet Archive** — хаос из сканов.

Фиды `trailers.apple.com` отдают HTML. Apple убрала кино из открытых фидов · ❌ (был главным кандидатом на «превью как у Deezer»)

- 2026-08-22 · **Фон витрины — динамический, от контента** (grill Q10): берём **один кавер первого идущего на витрине блока** (кино / книга / музыка), сильно скейлим и блюрим по параметрам Фигмы (ширина ×2 экрана = 804pt, blur 100, opacity 0.4, смещение −201/−81). Меняется вместе с контентом · так и задумано в макете: экран 1 зелёно-тёмный, экран 2 тёплый красный — цвет наследуется от обложки · ✅
- 2026-08-22 · **Живость ленты: каскадное появление + лёгкий скролл-параллакс слоёв** (кавер, подпись, кнопки движутся с разной скоростью, эффект едва заметный). Гиро-параллакс не берём · ✅
  - **Приоритет №1 — производительность: скролл должен быть идеально плавным, 120 fps (ProMotion), без фризов.** Следствия для реализации: `LazyVStack` вместо VStack; `drawingGroup()`/растеризация тяжёлых blur-слоёв; ambilight считать один раз, не пересобирать на каждый кадр скролла; видео в карточке проигрывать только когда она в зоне видимости; `CADisplayLink`/`TimelineView` только у видимых анимаций; замер через Instruments (Animation Hitches) до и после. Каждый эффект, который роняет фреймрейт, режем или запекаем.
- 2026-08-22 · **Витрина «Плюс» строится жёстко по макету** (grill Q7): точная последовательность 7 карточек и вся геометрия из Фигмы (нерегулярные отступы 20–66pt, наезды карточек друг на друга, выход за края экрана — контент ленты не клипать). Контент подгружается из API в те же слоты · пиксель-в-пиксель важнее генеративности; шаблонная лента ослабила бы точность вёрстки · ✅
- 2026-08-22 · **Кино-API = kinopoisk.dev (ПоискКино)** — ключ пользователя проверен запросами, работает (grill Q9). Заголовок `X-API-KEY`, ключ лежит в `_secrets/APIKeys.swift` (гитигнор), в документацию не пишем · это буквально тот же источник, что и в реальном Кинопоиске: русские названия, описания, постеры Яндекс-CDN · ✅
  - **Подтверждение попадания в макет**: подпись к фильму в Фигме («…уборщик ищет красоту в каждом мгновении. Шедевр Вима Вендерса о магии жизни») — это поле `shortDescription` из ответа API. Значит копирайт карточек берём именно оттуда, а не из `description`.
  - Проверено: `/v1.4/movie/search?query=`, `/v1.4/movie/{id}`, `/v1.4/movie?id=&id=` (батч), `/v1.4/list` (302 подборки, включая «По подписке Плюс», «Фильмы, которые стоит посмотреть», «Блокбастеры» — прямой аналог Deezer-чартов для витрины).
  - **Постеры**: Яндекс-CDN `avatars.mds.yandex.net/get-kinopoisk-image/<id>/<uuid>/<size>`; размер подставляется в URL как у Deezer. Рабочие: `300x450`, `600x900`, `1920x1080`, `x1000`, `orig` (955 КБ). Нерабочие: `1000x1500`, `1440x2160` → 404. Для карточки 180×270@3x брать `600x900`, для фона — `orig`/`1920x1080`. Есть также `backdrop` (1344×756) и `logo` (PNG с прозрачностью — аналог логотипа «ТВИН ПИКС» в макете!).
  - **Лимиты**: заголовок `x-ratelimit-limit: 5` (в секунду), суточная квота бесплатного тарифа ~200 запросов в заголовках не видна. Вывод: **дисковый кэш обязателен** (CurationCache), запросы батчить через `/v1.4/movie?id=&id=`.
  - **Трейлеров нет**: поле `videos` на бесплатном тарифе = `null`. Источник воспроизводимого видео ищем отдельно.
  - `kinopoiskapiunofficial.tech` этим ключом **не** открывается (401) — это другой сервис, регистрироваться там не нужно.

- 2026-08-22 · **Action bar: состояние определяет последний активный контент** (grill Q5), не активный таб. Плееры (музыка/кино/книга) = быстрый возврат к продолжению прослушивания/просмотра/чтения. Ничего не потреблялось → состояние `search` · ✅
  - **Геометрия — две зоны, всегда во всю ширину бара**: один элемент широкий (занимает всё оставшееся место), второй компактный. Компактные поиск и музплеер — **всегда круг 60×60**; компактные киноплеер (88×54) и книгоплеер (44×60) — своей ширины (в макете они и есть «компактные», развёрнутого состояния у них нет).

Реализация: один persistent HStack, анимируются ширины/opacity на живых вью (скрытые слои остаются в дереве с opacity 0 — так и собрано в Фигме), никаких if/else-подмен, никаких пересозданий вью.
  - **Тап по чипу кино/книги** в прототипе ничего не открывает (полноэкранные видеоплеер и читалка — позже; в макете чипы нарисованы «расширенными» именно потому, что тап должен вести в них).

  - **Плейсхолдер поиска (grill Q6)**: фразы «Хочу послушать… / почитать… / посмотреть…» **авто-сменяются по кругу**. Визуально — плавная кросс-смена одного тайтла на другой **сверху вниз**; реализация свободная (стопка с прокруткой из макета — артефакт Фигмы, можно проще). **Троеточие анимируется отдельно, дискретно: 1-2-3-1-2-3 точки**.
  - **Клавиатура**: тап по полю поиска поднимает клавиатуру, **action bar поднимается над ней**. При активации поиска инпут плавно расширяется, сжимая музплеер в круглый компактный вид. Сам экран поиска пока не делаем — но вёрстка бара сразу закладывается под работу с клавиатурой.
