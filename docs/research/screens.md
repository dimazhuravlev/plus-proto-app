Repo root: `/Users/dimazhuravlev/Repos/MusicPlayer/MusicPlayer/`. All paths below relative to that. Dark-only app (`.preferredColorScheme(.dark)`, black everywhere), custom fonts (Yango), custom chrome (no system nav/tab bars anywhere).

## 0. App shell (context all screens live in) — `MusicApp.swift`
- `AppRootView` (MusicApp.swift:30) creates ~9 `@StateObject` env objects injected globally: `GyroManager`, `DebugPanelState`, `ShowcaseNavState`, `ShareOverlayState`, `OverflowMenuState`, `NowPlayingState`, `CollectionState`, `OfflineModeState`, `ContentCurationManager.shared`. Data preloads in `.task { await curationManager.loadInitial(); ...loadRemainingInBackground() }` (MusicApp.swift:75-80).
- `MainContentView` (MusicApp.swift:104) is a hand-rolled tab controller: `enum AppTab { showcase, collection, player }` (MusicApp.swift:92), `switch activeAppTab` in a ZStack (MusicApp.swift:185-254). Showcase and Collection each get their own `NavigationStack(path:)` (MusicApp.swift:188, 242); Player is stack-less full-screen.
- **Fixed chrome pattern**: TopNavBar and BottomBar are NOT inside the NavigationStacks — they're overlaid in the outer ZStack (`VStack { TopNavBar; Spacer() }` at MusicApp.swift:281-296; `VStack { Spacer(); BottomBarV2 }` at MusicApp.swift:299-318) so they never participate in push transitions. Detail screens signal `showcaseNavState.isShowingDetail = true` in `.onAppear` to hide the global TopNavBar (MusicApp.swift:281 condition), and render their own `NavBar` with back button.
- **Showcase sub-tab switching** (For You / Trends / Spiritual): NOT a TabView. `switch pendingTab` renders one showcase at a time (MusicApp.swift:197-214); transition = 2-phase fade+blur: `isTransitioning=true` → opacity 0 + blur 4pt over 0.3s (`.smooth`), after 0.3s swap `pendingTab`, then fade back in (MusicApp.swift:218-237).
- Overlays above everything: `ShareOverlay` (zIndex 100), `OverflowMenu` (zIndex 101) — presented via env-object state, `.transition(.opacity)`, `.id(presentationID)` (MusicApp.swift:321-334).
- `ShowcaseNavState` (MusicApp.swift:85-89): `isShowingDetail` + `requestPopToRoot: Int` (incremented to force ShowcaseFeedView to reset its navigationDestination flags).
- MusicApp.swift:157-913 is offline-flash choreography (Metal shader overlay, CoreHaptics roulette pattern, AVAudioPlayer sound, epoch-guarded Task timeline with deferred nav redirect at cover=0.55) — elaborate but self-contained; pattern worth copying: **do heavy tab/root switches under a full-screen opaque overlay, deferred via `DispatchQueue.main.async` inside `withCheckedContinuation`** (MusicApp.swift:571-583) to avoid frame hitches.

## Data layer pattern — `Services/ContentCurationManager.swift` (442 lines)
- Singleton `@MainActor ObservableObject`, injected as environmentObject. Published: `curatedTracks`, `featuredAlbums`, `newReleases`, `albumGroups: [(title, [AlbumCardItem])]`, `downloadedPlaylistShowcase`, `myVibeGeneratorTracks`.
- Lazy-load API shape: `loadInitial()` (app launch), `loadRemainingInBackground()` (post-launch loop), `loadNewReleasesIfNeeded()` / `loadMyVibeGeneratorTracksIfNeeded()` (screen `.task`) — each guarded by `hasLoaded*` flags; in-flight Task dedup for MyVibe (lines 68-96).
- Source: Deezer free public API via `DeezerService.shared` (seed playlist IDs → artist pool → artist albums filtered by allowed genre IDs → shuffled queue → batches of 10 via `withTaskGroup`). `albumGroups` frozen after first non-empty build so background loading never re-shuffles visible carousels (lines 39-40, 310-315). Deezer CDN image-size upgrade trick `/\d+x\d+-/ → /1000x1000-/` (lines 347-355).
- Screens always render instantly with whatever is loaded; remote enriches later (Album's `newReleaseContext ?? loaded ?? mock` chain is the template for mock+API hybrid).

## Key takeaways for the heterogeneous-card feed of the new app
1. Existing feed = `ScrollView → VStack(spacing: 32)` of section views; sections are self-contained components taking (title, items, callbacks). To scale to a long heterogeneous feed (movie/album/book/vibe/continue-cards) the same shape works but should become `LazyVStack` + an enum-driven `ForEach` over section models — the codebase has no such abstraction yet; ShowcaseFeedView's override/injection params are the closest precedent.
2. Card taxonomy already spans the needed range: small square card w/ 2-line meta (AlbumCard), image-only card (PlaylistCard), 85%-width hero card with internal buttons (NewReleaseCard), full-bleed video/shader hero (Generator), 3-row track pager (TrackCarouselView). Continue-watching/reading cards would be new but compose from the same primitives (CachedAsyncImage + VariableBlur + gradient stops + grain).
3. Navigation convention: state-flag/`item:` `navigationDestination`s declared on the feed root; fixed chrome outside NavigationStack; `isShowingDetail` env flag to swap global header for per-screen NavBar; `requestPopToRoot` counter for programmatic pop.
4. Scroll-linked animation toolkit: PreferenceKey offset tracking (NavBar.swift:5-31) with hard thresholds (360) and ramps ((offset−200)/80); UIKit KVO bridge for overscroll (Collection.swift:275-369); VariableBlur package (`import VariableBlur`) used in every header/footer treatment; 16-stop hand-tuned black gradients (repeated verbatim in 4+ files — worth centralizing in the new app).
5. Appear animations vocabulary: staggered chip slide-in (Playlist.swift:310-341), title crossfade (Wizard), showcase tab fade+blur swap (MusicApp.swift:218-237), entrance scale 0.9→1 with chrome offset+opacity (offline flow), shake+haptics sequence (Wizard.swift:272-302).

- Continue-watching / continue-reading cards: what progress model and behavior (resume target, progress bar, dismissal)? Nothing analogous exists in MusicPlayer.
- Does Алиса appear as a feed card / hero block (Generator-style shader hero is the obvious slot) or as a separate surface (overlay/sheet)?
- Which free public APIs per domain (Deezer is wired for music; TMDB/Kinopoisk-unofficial for movies? Google Books/OpenLibrary for books?) and should each domain get its own CurationManager clone or one shared feed-composition service?
- Player screen: does the new app need the TikTok 2D pager player at all, or only mini-player chrome (BottomBarV2/MiniPlayerV2)?
- Should the offline-mode flash/pull machinery (large share of MainContentView complexity) be carried over or dropped for the prototype?
