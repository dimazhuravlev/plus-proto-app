# Прототип супераппа

iOS/SwiftUI дизайн-прототип супераппа: кино, книги и музыка в одном приложении
и общая коллекция на всё.
Не продовое приложение — исследование интерфейса на живых данных бесплатных публичных
API (kinopoisk.dev, Deezer, Google Books) и моках там, где данных нет.

Работа ведётся по макетам из Фигмы. Точка входа для того, кто продолжает работу, —
[CLAUDE.md](CLAUDE.md): правила, принципы, грабли и открытые вопросы.

## Что нужно

- macOS с **Xcode 26.x** (проект собирается на 26.3). Деплой-таргет iOS 26.0, так что
  Xcode 15/16 не подойдёт — нужен iOS 26 SDK и его симуляторы.
- Симулятор **iPhone 17 Pro** — вся вёрстка считается от ширины 402 pt. Другой симулятор
  запустится, но макетные замеры перестанут сходиться.
- ~30 МБ на клон: шрифты и видео лежат в репозитории, отдельно докачивать нечего.
- Ключи API не нужны, чтобы начать: без них прототип идёт на моках (см. «Ключи»).

## Установка

```bash
git clone https://github.com/dimazhuravlev/plus-proto-app.git
cd plus-proto-app
./scripts/setup.sh
```

Скрипт проверит Xcode, создаст `PlusProtoApp/APIKeys.swift` из шаблона
[APIKeys.example.swift](APIKeys.example.swift) (существующий не перезапишет) и соберёт
проект — первая сборка дольше остальных, тянется единственная зависимость
[VariableBlur](https://github.com/nikstar/VariableBlur) через SPM.

Дальше — руками:

```bash
open PlusProtoApp.xcodeproj
```

Схема `PlusProtoApp`, симулятор iPhone 17 Pro, `Cmd+R`.

Если предпочитаешь без скрипта, минимум такой:

```bash
cp APIKeys.example.swift PlusProtoApp/APIKeys.swift && open PlusProtoApp.xcodeproj
```

### Xcode ругается на подпись

В проекте прописана команда разработчика владельца (`DEVELOPMENT_TEAM = Z55ZV5538M`),
и у чужого Apple ID к ней доступа нет. Для симулятора подпись не нужна вовсе: открой
target `PlusProtoApp` → Signing & Capabilities и либо выбери свою команду, либо очисти
поле. На сборку в симулятор это не влияет.

## Ключи

Ключей в репозитории нет и не будет: `PlusProtoApp/APIKeys.swift` в `.gitignore`.
Шаблон с пустыми строками — [APIKeys.example.swift](APIKeys.example.swift).

**Пустые ключи — рабочее состояние.** Проект собирается, витрина идёт на моках
(то же, что флаг `-debugMockFeed`), в консоль уходит предупреждение. Видно всю вёрстку,
хром, анимации, морф action bar, экраны сущностей на моковых данных. Не работает то, что
требует сети: живая витрина, поиск, карточки тайтлов, альбомы Deezer.

Чтобы включить живые данные, есть два пути.

1. **Попросить ключи у владельца репозитория** — быстрее всего. Присылаются личным
   сообщением, вписываются в `PlusProtoApp/APIKeys.swift`. Минус: суточная квота
   kinopoisk.dev (200 запросов) делится на двоих, и в день активной работы её можно выбрать.
2. **Получить свои** — 5–10 минут, зато своя квота:
   - **kinopoisk.dev** (обязателен, на нём кино и поиск): телеграм-бот с
     [kinopoisk.dev](https://kinopoisk.dev) выдаёт бесплатный ключ сразу. Вписывается
     в список `kinopoisk` — их можно несколько, сервис переключается на следующий, получив
     403 по квоте.
   - **Google Books** (опционален, только описания книг): консоль Google Cloud → новый
     проект → включить «Books API» → Credentials → API key. Обложки книг идут
     без ключа, так что без него книжный блок просто останется моковым.

Deezer (музыка) ключа не требует вообще.

Ключ подхватывается на запуске: вписал — перезапустил приложение — витрина живая.

## Отладочные флаги

Прототип умеет поднимать себя в нужном состоянии без тапов — этим снимают скриншоты и
воспроизводят жалобы. Из Xcode: Product → Scheme → Edit Scheme → Run → Arguments →
Arguments Passed On Launch. Из терминала:

```bash
xcrun simctl launch booted com.dima.PlusProtoApp -debugMockFeed -debugActionBar music
```

| Флаг | Что делает |
| --- | --- |
| `-debugMockFeed` | витрина на моках, без сети — для сверки вёрстки с макетом |
| `-debugTab <plus\|music\|kinopoisk\|books\|collection>` | стартовый таб |
| `-debugActionBar <search\|music\|movie\|book>` | режим action bar |
| `-debugFrozenFeed` | зафиксировать зерно выборки, чтобы витрина повторилась |
| `-debugNoSplash` | без заставки — нужен прогонам, которые снимают кадры по таймеру |

Полный список и приёмы проверки — [docs/DEBUG.md](docs/DEBUG.md). Флаги из кода
не удаляем: ими воспроизводятся жалобы.

## Где что лежит

```
PlusProtoApp/
  App/           корень композиции, заставка, отладочные пробы
  Chrome/        постоянный хром: action bar, таббар, скримы
  Screens/       экраны — витрина, альбом, тайтл, книга, поиск
  Showcase/      блоки и карточки витрины
  DesignSystem/  токены, шрифты, переиспользуемые примитивы
  Services/      сетевые сервисы и кэши (kinopoisk.dev, Deezer, Google Books, обложки)
  State/         глобальные состояния: навигация, action bar, поиск
  Data/          модели и моки
  Fonts/         YS Display и YS Text
docs/            DEBUG (флаги и приёмы проверки), research, specs, snippets
scripts/setup.sh первая установка
```

## Как вносить изменения

Ветка → pull request → зелёная сборка → Squash and merge. В `main` напрямую не пушим.
Правила целиком — [CONTRIBUTING.md](CONTRIBUTING.md).

Коротко про сам код:

- **Токены — только переиспользуемые значения** в `DesignSystem/Tokens.swift`. Одноразовый
  градиент или тень живут локально у компонента: токен ради единственного вызова не заводим.
- **Магические числа анимаций** — именованными константами в config-enum рядом с компонентом.
- **Файлы добавляются простым созданием на диске**: папка `PlusProtoApp` синхронизирована
  с таргетом, `.xcodeproj` править не нужно. Обратная сторона — любой `.swift`, положенный
  внутрь, попадает в сборку.
- **«Почему» записывается сразу**: локальное решение — комментарием у кода, сквозное
  правило — строкой в [CLAUDE.md](CLAUDE.md). Без причины через неделю решение выглядит
  случайным.
- **Проверяет глазами человек, не агент.** Приёмы верификации, выработанные на проекте, —
  [docs/DEBUG.md](docs/DEBUG.md).

Работаешь через Claude Code — [CLAUDE.md](CLAUDE.md) он подгрузит сам: там правила
проекта, принципы и открытые вопросы.

## Оговорка

Дизайн-прототип, сделанный для исследования интерфейса. Не связан ни с одним
коммерческим продуктом и его кодом, не предназначен для распространения как приложение.
Шрифты и данные из публичных API принадлежат их правообладателям.
